# 垫话配置：她开口前的第一声

> 用户刚说完、AI 还没开始回话的那一两秒，她会先播一小句"嗯？""在呢"。
> 这份文档只讲**这句话说什么、怎么说、怎么改**。改完保存就生效，不用重启。

---

## 一句话原理

垫话的唯一任务是"填住等待空档"，让你知道她听到了。它：

- **不进对话历史**，不占一轮对话；
- 走的是正常 TTS，所以字幕、口型、回声抑制都一致；
- 说什么由 `resources/backchannel.json` 决定，按"你像在提问 / 在陈述"选语气，
  还会避开最近用过的几句。

---

## 文件在哪

```
resources/backchannel.json
```

- 文件不存在时，**启动会自动生成**一份默认的；
- 删掉也没关系，下次启动会重建；
- `resources/config.yaml` 里的 `system.backchannel.phrases` 只是 JSON 不可用时的兜底，
  平时请改 JSON。

---

## 表怎么填

```json
{
  "_comment": "随便写，程序会忽略这一行",
  "avoid_repeat_window": 3,
  "phrases": [
    { "text": "嗯？",   "weight": 3, "tags": ["question"] },
    { "text": "怎么啦", "weight": 2, "tags": ["question"] },
    { "text": "嗯…",    "weight": 2, "tags": ["statement"] },
    { "text": "嗯嗯",   "weight": 2, "tags": ["statement"] },
    { "text": "在呢",   "weight": 1, "tags": ["any"] },
    { "text": "你说",   "weight": 1, "tags": ["statement"] }
  ]
}
```

| 字段 | 类型 | 说明 |
|---|---|---|
| `phrases[].text` | 字符串 | 要念的话。**建议 1~4 个字**，太长会推迟真正回复的开播 |
| `phrases[].weight` | 数字 | 相对权重，越大越常被选中，默认 `1` |
| `phrases[].tags` | 数组 | `question`（你像在问）/ `statement`（你在陈述）/ `any`（通用），可多选，默认 `any` |
| `avoid_repeat_window` | 数字 | 最近几条不重复，默认 `3`。设 `0` 表示允许连续重复 |
| `_comment` | 任意 | 注释用；JSON 本身不支持注释，写个下划线字段最省事 |

`phrases` 里也可以直接写字符串（等价于 `{"text": "...", "tags": ["any"]}`）：

```json
{ "phrases": ["嗯？", "在呢"] }
```

## 问句 / 陈述是怎么判断的

很轻的启发式：句子里有问号，或含"吗 / 什么 / 怎么 / 为什么 / 哪 / 谁 / 几点 / 多少 /
是不是 / 能不能 / 要不要"之类，就按 `question` 选；否则按 `statement`。
判错了也不会出问题，只是语气可能不太贴。

---

## 常见调整

| 你想要的 | 怎么改 |
|---|---|
| 别老是"嗯？"，显得呆 | 多加几条，或把"嗯？"的 `weight` 调小 |
| 更黏人、更像妹妹 | 加 `"怎么啦"`、`"在呢"`、`"你说"`、`"我听着呢"` |
| 别太频繁，一句一嗯很烦 | `system.backchannel.min_interval_s` 调大（默认 2 秒）；只想每次搭话第一句回一次，设成 `3600` |
| 话太长，回复被推迟 | 保持每条 ≤ 4 个字；超过 1 秒的句子会明显延后真正回复 |
| 完全不要垫话 | `system.backchannel.enable: false` |
| 只想换音色，不想重配文本 | 不用动 JSON；换 TTS 音色后音频缓存会按指纹自动重建 |

## 生效方式（热加载）

1. 编辑并保存 `resources/backchannel.json`；
2. **下一次她开口**就会用新配置（按文件修改时间检测，不用重启）；
3. 新增的句子需要先用当前音色合成：
   - 启动时会把所有句子后台预热一遍；
   - 你新加的句子在第一次触发时如果还没合成好，**这次先不垫**（不让你多等），
     后台合成，下一次就能用；
4. 合成结果缓存在 `resources/cache/backchannel/`，文件名带音色指纹，换音色自动失效重建。

想确认有没有生效：看日志里的 `Backchannel: '在呢'`（DEBUG 级），或者看缓存目录里是否多出
新的 wav。

---

## 和"太呆"有关的两个设计取舍

- **为什么不用大模型现生成？** 那会把垫话变成另一次 LLM 调用，延迟比等待还长，失去意义。
  文本是预先合成好的，播放时零延迟。
- **为什么不干脆省略？** 省略会让她在你话音落后沉默好几秒，听感更像"没听见"。
  一两声"嗯"是最便宜的存在感。

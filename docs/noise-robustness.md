# 抗噪手册：别让键盘和咳嗽骗了机器人

> 这份文档只讲三件事：
> 1. 机器人怎么判断"你在跟它说话"；
> 2. 为什么以前老被键盘、咳嗽、环境噪音骗；
> 3. 被骗的时候，你该动哪个开关。
>
> 不需要懂信号处理。代码在 `devices/noise_gate.py` 和 `devices/microphone.py`，
> 配置在 `resources/config.yaml` 的 `system.noise` 段，改完都要重启主程序才生效。

---

## 30 秒看懂

**以前**：麦克风每 30 毫秒问一次 webrtcvad"这一小段像人声吗"。像，就攒着；攒够大约 1 秒，
就当成你说了一句话，送去识别。

**毛病**：键盘的"嗒"、咳嗽、挪椅子、关门，在 webrtcvad 听来都很像人声。它只有一个判据，
没人复核，于是就出现了"我只是打了个字，她突然回我一句"。

**现在**：在 webrtcvad 后面加三道复核——

> **你此刻在打字吗？够响吗？这声音像人吗？**

三道都过了，才会把这句话送去识别。打断（你说话时她停下来听你说）用的是同一套标准，
而且更严：必须"连着说 1.2 秒像人话"，敲键盘不算。

这些检查有个重要性质：**它们只会让机器人"少理你"，不会让它"多理你"。** 所以调严了顶多是
反应少一点，不会凭空冒出对话。

## 1. 以前的三个糟心场景

| 场景 | 以前会发生什么 |
|---|---|
| 安静房间，你敲了几下键盘 | 攒够帧数后当成一句话 → 识别出一句莫名其妙的话 → 她回你一句 |
| 你咳嗽两声 | 同上，而且咳嗽往往比说话还响，更容易过 |
| 她正在说话，你敲键盘 | 被当成"用户在插话"，于是她**立刻闭嘴**，话说到一半被切断 |

这三个场景看着像三个 bug，其实是**同一个原因**：判断"有没有人在说话"只看了一道关卡，
而这道关卡（webrtcvad）本来就不是为键盘、咳嗽设计的。

---

## 2. 现在她是怎么听你说话的

### 2.1 一帧一帧地看

麦克风把声音切成 **30 毫秒**一小段（叫一帧），一帧一帧地判断。一秒钟大约有 33 帧；
你连续说话时，这些帧大部分都会被判成"有人声"。

### 2.2 第一道：你是不是在打字

只要**最近 250 毫秒内你按过键**，这一帧就直接不算"人声"。

道理很朴素：键盘声和你手指的动作是同时发生的，而你说话时手通常不在键盘上。
这条几乎不会误伤，是最划算的一道检查。

> 例外：如果你习惯**一边说话一边打字**，这条会吞掉那几个字。把
> `keyboard_suppress_ms` 调到 120~150 会宽松一些。

### 2.3 第二道：够不够响

声音要同时满足两个条件才算数：

- **绝对够响**：比一个很低的固定门槛响（否则就是远处的动静、风扇声）；
- **比背景吵得明显**：至少比"房间平时的底噪"响 2.5 倍（大约 +8 分贝）。

第二个条件是关键，而"平时有多吵"不是写死的数字，是机器人**自己慢慢听出来的**：
它只在"确认没人说话、也没在放音"的时候，悄悄记下房间的噪声水平。

这样一来：

- 换了房间、开了空调、换了麦克风，不用你手改配置，它自己会适应；
- 也不会因为你自己说话，把门槛越抬越高（说话的时候它不学底噪）。

**这道门管什么**：电视声、隔壁说话、风扇突然变大这类"远处、偏轻"的声音。
**不管什么**：咳嗽和键盘——它们太响了，声音大这条拦不住。

### 2.4 第三道：这声音像不像人

人说话有音调、有元音，能量集中在几个固定的频段，听起来"有起伏、不刺耳"。
而键盘点击、摩擦、白噪音是"唰"的一下，能量又宽又平。

用三个很直观的指标来判断（不用记公式，理解意思就行）：

| 指标 | 大白话 | 人说话 | 键盘 / 噪声 |
|---|---|---|---|
| 过零率 | 波形"来回抖"得多不多 | 抖得慢 | 抖得飞快 |
| 谱平坦度 | 声音是"有峰有谷"还是"一片平原" | 有峰有谷 | 一片平原 |
| 语音带占比 | 能量有多少落在人声的频段（200~3800 Hz） | 九成以上 | 不到一半 |

这三个数字是从真实录音里量出来的：**人说话**大约 0.1 / 0.01 / 0.6~0.9（不同麦克风差异较大），
**白噪声**大约 0.5 / 0.56 / 0.45，两者分得很开，所以判定很稳。

**为什么是"整句一起看"，而不是每帧都判？**
因为中文里的"是""四""吃"开头那一下，本身就长得像噪声。如果每帧都卡，这些字会被咬掉。
换成看整句的**中位数**，一句话里正常音节占多数，就不会冤杀。

### 2.5 最后还要过一遍"整句体检"

前面都是逐帧的。等这一句结束（连续安静 1.2 秒），还会整体再看一次：

- **够长吗**：语音部分至少 **0.4 秒**（约 13 帧）。这个门槛刻意放得很低——"好的""等一下""你说啥"
  这类几个字的短句也要能进去；挡住噪声靠的是前面那些检查，不是靠时长；
- **说得密吗**：真正有声音的帧，占从第一个字到最后一个字的比例。
  你说话是连着说的，接近 100%；而"边打字边零星触发"是稀稀拉拉的，密度很低；
- **像人吗**：把整句的中位数拿去过 2.4 的三条线。

三条都过了，才会把这段音频送去识别。

> 如果没过，日志里会写清楚是哪一条没过（`too_short`、`low_density`、`zcr` 等），
> 方便你判断该调哪里。

## 3. 打断：为什么敲键盘也能打断，现在怎么修的

### 以前是怎么判断"你在插话"的

她说话的时候，麦克风没关（全双工），只要累计有 1.2 秒的声音被判成"人声"，就认为你在插话，
于是立刻停下、清空待播的语音。

问题出在**"清零"太慢**：要连续安静 1.2 秒，计数才归零。可她一段话可能说十几秒，
中间断句、换气、语气停顿到处都有，这段时间里你零星敲几下键盘，误判就一点一点攒起来，
最后凑满 1.2 秒——于是被"打断"。

### 现在的规则

一条声音要算作"你在插话"，必须同时满足：

1. **不是打字**（最近 250 毫秒内没按键）；
2. **够响**（至少过了绝对静音门）；
3. **逐帧也像人声**（这一帧的频谱要过更严的线）；
4. **回声消除器也认为像人声**（全双工下还有一个概率门槛）。

而且：

- **停 0.35 秒就清零**（原来是 1.2 秒），零星误判攒不起来；
- **她刚开始出声的前 0.3 秒不计数**，给回声消除器一点时间稳定，避免开头的爆音误触发。

一句话总结：**要打断她，你得连着说 1.2 秒像人话。敲键盘、咳嗽、回声残响都不算。**

> 代价：如果你说话开头很轻，或者一句话中间停顿超过 0.35 秒，打断会变慢，甚至需要重新说。
> 觉得太慢就把 `barge_in_gap_ms` 调大一点（见第 6 节）。

## 4. 顺手修掉的一个小毛病：句尾那一秒静音

原来的流程里，一句话说完要等 1.2 秒安静才算结束，而这 **1.2 秒静音会原样塞进音频里**
一起送去识别。静音太长，识别模型容易"无中生有"地吐出"嗯""啊"。

现在改用：仍然等 1.2 秒才判定"说完了"，但**只把最后 0.3 秒静音**交给识别。
判句子的时机没变，送出去的内容变干净了。

## 5. 读懂日志（这是调参的唯一依据）

每说完一句，日志里会出现一行。比如：

```
[VAD] dur=1800ms speech=60 span=60 (100%) rms=964(-30.6dBFS) floor=210 snr=13.2dB zcr=0.07 flat=0.00 band=0.88 -> ACCEPT
[VAD] dur=1800ms speech=60 span=60 (100%) rms=769(-32.6dBFS) floor=210 snr=11.3dB zcr=0.50 flat=0.55 band=0.44 -> REJECT(zcr)
```

怎么读：

| 字段 | 意思 | 正常值 |
|---|---|---|
| `dur` | 这句话里有声音的总时长 | 你的正常句子 0.8~5 秒 |
| `speech` / `span` | 有声音的帧数 / 从头到尾跨了多少帧 | 连着说话时两个数差不多 |
| `(100%)` | 语音密度 | 说话 85%~100% |
| `rms` / `dBFS` | 这句话的典型响度 | 说话约 -35 ~ -20 dBFS |
| `floor` | 学到的房间底噪（`?` 表示还在学） | 安静房间 100~300 |
| `snr` | 比底噪响多少分贝 | 说话 8~25 dB |
| `zcr` / `flat` / `band` | 像不像人的三个指标 | 说话 0.1 / 0.01 / 0.9 上下 |
| 末尾 | `ACCEPT` 收下了 / `REJECT(原因)` 扔掉了 | — |

**最有用的用法**：把"被误触发的那几条"和"你正常说话的几条"放在一起看。
如果误触发那条的 `zcr`、`band` 和你说话差很远，说明是宽带噪声，调频谱那条线就行；
如果指标差不多、只是 `span` 特别大、密度很低，那就是"稀疏触发"，该调密度那条线。

> 日志开关是 `log_utterances`。不想看就关掉，但调参期间建议开着。
> 现在**所有拒绝都会打一行带指标的 INFO 日志**（包括以前只在 debug 里、根本看不见的
> `too_short`），所以"我说了却没反应"的情况一定能查到原因。

## 6. 觉得不对时，改哪个开关

先按默认值跑一天，看日志再动手。常见症状与对应旋钮：

| 症状 | 先改这个 | 还不行再改 |
|---|---|---|
| 打字还是会触发 | `keyboard_suppress_ms`：250 → 400 | `max_zcr`：0.22 → 0.18 |
| 咳嗽还是会触发 | `max_flatness`：0.45 → 0.35 | `barge_in_min_speech_prob`：0.65 → 0.75（只影响打断） |
| 环境噪声偶尔触发 | `snr_margin`：2.5 → 3.0 | `abs_floor_rms`：350 → 450 |
| 我轻声说话被吃掉 | `snr_margin`：2.5 → 2.0 | `abs_floor_rms`：350 → 250 |
| 只说几个字（"好的""等一下"）没反应 | `vad_min_speech_ms`：400 → 300 | 看日志里是不是 `REJECT(too_short)`，是就再降 |
| 说话被 `REJECT(band_ratio)`（明明是真说话） | `min_band_ratio`：0.50 → 0.45 | 关掉 `spectral_check` 对照一下 |
| 说话被 `REJECT(low_density)`（中间 pause 较多） | `min_speech_ratio`：0.30 → 0.15 | — |
| 打断太容易被误触发（键盘/咳嗽仍会把她切断） | `barge_in_gap_ms`：350 → 250 | `barge_in_min_speech_prob`：0.65 → 0.75 |
| 打断太迟钝（你喊了她不停） | `barge_in_gap_ms`：350 → 500 | `barge_in_grace_ms`：300 → 200 |
| 完全不想改行为，只想看数据 | `enable: false`（句尾裁剪仍生效） | — |

> 小提醒：`vad_min_speech_ms` 和 `vad_silence_hangover_ms` 属于 `system:` 段（不在 `noise:` 里）。
> 旧版 `resources/config.yaml` 里可能没有这两个键，新版已经补上了；如果你看到它们缺失，
> 手动加到 `system:` 下面即可，否则生效的是代码默认值（现在 400 / 1200）。

## 7. 现在仍然做不到的事

老实说清楚边界，免得白调参数：

1. **电视、视频、隔壁清楚的说话声** —— 频谱上和真人没区别，靠现在这些规则分不出来。
   要解决得加"声纹确认"或"唤醒词"，是另一件事。
2. **凑得很近的咳嗽** —— 又响又有共振峰，可能还是会漏进来。调低 `max_flatness` 能缓解。
3. **一边打字一边说话** —— 键盘抑制会把那几帧一起吞掉，听起来像吞字。
4. **麦克风的自动增益 / 音频增强** —— 会让"够不够响"这条失准。建议在 Windows 声音设置里
   关掉麦克风的"增强 / 自动增益"。
5. **噪声被识别成文字** —— 少数情况下识别模型还是会把噪声写成"嗯""啊"，这类结果目前会
   进入对话。后续可以在文字层再加一道"纯语气词就丢弃"的过滤。

## 8. 怎么确认它在正常工作

```bat
ZRExistence_venv\Scripts\python.exe -m pytest tests/devices/test_noise_gate.py -q
```

应该看到 `13 passed`。这些测试用合成音频验证了：静音必拒、人声（男女基频）必过、
键盘点击必拒、白噪声必拒、语音太稀必拒、底噪能自适应、打断不会被噪声触发。

日常使用中，最直接的确认方式是看日志：正常说话是 `ACCEPT`，打字/咳嗽应该几乎没有输出，
或者出现 `REJECT(...)` 而不是一句莫名其妙的回复。

## 9. 想一键退回旧行为

```yaml
system:
  noise:
    enable: false
```

关掉后只剩 webrtcvad 判断（句尾静音裁剪仍保留）。适合"怀疑是新逻辑导致我不灵敏"时做对照。

## 附：配置速查（一般不用动）

| 键 | 默认 | 干什么的 |
|---|---|---|
